# 现役依赖上的现金报告维护

该维护分支基于已验证的原运行源码，回移现金观察附件及只读挂单保护；原依赖锁、策略决策、原生持仓缓存来源和部署入口保留。
它不将主分支的新策略或依赖整体升级到现役账户，也不改变账户资金、保留额、风险政策或运行状态。

原组合快照已经读取的`accountValues`同时保留目标账户的独立现金字段。原报告新增
`broker_cash_observations`，包含同一观察时间、币种、原生标签及原精度十进制文字。
无效和重复字段明确无效，原生持仓仍沿原缓存投影，不从成本价快照重新生成市值。
报告维护不增加券商请求、不绑定订单、不提交/修改/取消订单。

该附件只证明报告收到了什么。SettledCash、AvailableFunds和现金余额含义不同；附件不证明全部订单占款、可支用金额、实际收费计划或配置采用资格。缺失继续保留未知。

先用此分支冻结锁运行现金、持仓、报告和原执行回归，再由现有单服务发布入口指定准确维护提交，保留原配置及定时任务。零流量部署、流量采用、真实采集和保存读回分别核验；不以合成通过或健康检查冒充真实现金证据。
# 候选报告隔离

受保护维护读取使用固定请求头 `X-QSL-Maintenance-Cash: 1`，在连接前标记报告。
成功和失败报告均沿原writer保存到原私有前缀的 `maintenance-cash/` 子目录，
避免现役按月选择器把候选报告误选成最新生产报告。普通probe和执行报告的路径不变；
不改变运行目标、凭据、风险配置或发布者的版本绑定。

# 候选周期的只读挂单保护

执行与对账复用同一个 `load_read_only_open_trades`，调用原锁定 SDK 的阻塞式
`reqAllOpenOrders`，等待完成后合并响应和本地未解决的活动订单。相同 Trade 对象
只计一次，本地缓存为空不再代表没有其他 API 客户端挂单。读取最多等待 10 秒，
保留更短的原超时，并在成功、失败或超时后恢复 SDK 设置；不重试，不请求绑定、
撤单、修改或下单。该时限是接口读取期限，不是账户风险阈值。

受管标的存在活动订单时沿原路径停止；响应缺失、读取失败、相关订单缺账户或标的
时返回 `pending_orders_unavailable`，不以空列表替代。其他证券仍可能占用同账户现金，
尚不能核明金额及是否已经净入余额时，复用原新增风险 BUY 保护；不猜占款金额或重复
扣减。其他明确账户的订单不占用本账户预算。可核准的独立减仓仍须通过原风险、数量、
claim 和日锁检查，不能把其卖出款立即用于继续增仓。只有买入而无合格减仓的周期在
取得日锁前停止；后续完整新观察可重新判断，不修改旧结果或自动解除熔断。

这里的读取只覆盖同一 TWS/Gateway 登录会话可见的已提交 API 订单，不证明其他登录、
所有手工待办、转出或未净入费用均已覆盖。账户整体资金义务及真实采用仍需自己的来源；
本候选的源码、离线通过、真实读取和部署分别验收。原策略、预算、风险参数及依赖锁
不因本节改变，也不自动发布候选。
