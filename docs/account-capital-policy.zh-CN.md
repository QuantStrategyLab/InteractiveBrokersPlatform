# 账户资金范围、现金保留与定投：通用设计

状态：TQQQ/IBKR 人工离线现金政策接线已实现，复用既有合同；未启用账户、配置、定投转账或交易。私人选择与真实配置从受保护来源注入，开源代码不假定用户有工资、银行备用金或特定风险承受能力。

## 1. 账户资金范围由用户选择，现金规则由系统复用

用户先选择管理哪些账户。每个账户沿用已有 `CapitalBaseBinding`、来源绑定和执行边界。

| 情况 | 处理 |
|---|---|
| 所选券商账户的全部净资产均纳入管理 | 使用全账户范围与已核净值；预算随真实资金变化，无需每次手填固定本金 |
| 券商账户内有不参加策略的资金或资产 | 使用已有能力支持的明确范围、保留规则或上限；未支持的范围标记不可用，不伪装成全账户 |
| 账户已有现金保留规则，用于生活支出和交易费用缓冲 | 复用该规则在策略可分配现金中预留一次；不再为相同用途要求第二份预算 |
| 生活和应急资金已在系统外安排 | 可记录为用户声明；不强制导入银行账户、工资或家庭账单，也不再次扣一笔应急金 |
| 尚未选择范围或账户来源不完整 | 仅观察或解释预览，不假定“所有账户、所有资金均已授权” |

全部资金纳入管理并不要求满仓买证券。账户内保留的现金仍属账户资产，由同一资金规则管理。
未来覆盖所有账户，不代表账户间可以调拨资金，或同一物理账户能重复计入多个策略预算。

## 通用设置与个人配置的分界

开源层提供三档／高级模式、现金保留方式、配置校验、风险计算与状态保存等通用能力；每位部署者通过原配置入口选择自己的账户、资金范围、风险政策和现金要求。个人风险数字、资金用途和认可记录留在私有配置或讨论草案中，不写入共享策略、公开默认或测试 fixture。

个人资料用于其对应实例的适用性核查，不能成为其他用户的假设，也不要求所有用户申报工资、银行资产或家庭账单。账户已有同一用途的保留配置时直接复用，不重复提问或重复扣留。通用工程交付、个人政策完整性、实际配置启用分别验收；某位用户尚未决定个人数字，不阻止独立通用工程。当前对话确认尚未形成一个完整的通用问卷或配置产品，也未写入生产设置。

## 2. 直接复用现有 CashPolicy

现有 QPK `quant_platform_kit.common.runtime_control.CashPolicy` 已有
`cash_only`、`reserved_cash_ratio`、`reserved_cash_floor_usd`，以及
`effective_reserve_ratio()`、`reserved_cash_usd()`。IBKR 原配置、运行时及执行器已有相应链路，
不再增加第二套资金政策、现金账户或保留比例。

```text
有效保留比例 = max(账户配置比例, 策略已有保留比例)
应保留现金   = max(有效保留比例 × 已核账户净值, 已配置最低保留金额)
```

现有控制台已支持以下三种用户保留模式，直接复用，不新增同义选项：

| 模式 | 用户配置要求 | 原字段落点 |
|---|---|---|
| 按比例 | 按账户净值的一定比例预留 | `reserved_cash_ratio`；清除用户固定额覆盖 |
| 固定金额 | 至少保留指定金额 | `reserved_cash_floor_usd`；清除用户比例覆盖 |
| 两者结合 | 比例金额和固定额取较大值 | 同时提供两字段，仍用原 `max` 算法 |

界面另有沿用当前设置和取消额外保留的选项，它们不是第四、第五种计算公式。
所有选项仍受策略自身已有最低要求约束；“固定金额”表示最低要求，不保证最终现金恰好等于该金额。
界面模式、已保存草稿、部署目标两字段和实际生效值须分别展示；不能只看到字段支持就认定该模式已被选中，
也不能仅凭缺少固定额就断言它从未配置或线上已清零。

现有保存链只保存两项数值，没有独立的运行时 mode 字段，继续复用该表达即可。
按比例模式不要求再填写固定金额；在来源合同明确“未配置则沿用既有默认”的情况下可以解释默认来源，
读取失败或不知配置层级时仍是未知，不能冒充该默认。草稿里的移除覆盖 `null` 与显式零须保留区别。

比例与最低额是同一现金底线的两种表达，取较大值，不相加。已有零值和未配置、未读取、无效值须分开；
源码默认值不证明当前账户设置，部署意图也不等于实际运行版本已经消费。

当前 TQQQ/IBKR 通路以 USD 为单位，继续沿用现有字段。通用界面中的金额须显示币种；
其他币种不能仅改显示标签继续传入 `_usd` 字段，须由相应平台合同和有来源的 FX 处理，
未支持时明确不可用。本设计不扩展多币种执行。

界面应从同一份有效政策展示：保留比例、最低金额、当前实际要求、来源与时点。
高级设置若保留 `cash_floor_ratio`，须说明其为费用后组合现金比例约束，与资金可用性检查共同满足，
不能再扣一份相同的保留现金。

## 3. 分开检查配置净值与可花现金

配置净值决定组合规模；已结算、可支用且义务完整的现金决定现在能买多少。股票市值、保证金购买力、
银行存款或未来工资不能冒充该现金。

复用 UES 的现金证据桥与账户适配器：

```text
保留要求 → 原 reservations 证据 → reserved_cash
可花现金 = 已核 SettledCash − reserved_cash − 未重复计入的其他现金义务
```

如果券商标签已经净扣某项义务，先核口径，不能再扣一次。保留额先从净值或 SettledCash 扣掉，
随后又传入 `reserved_cash` 的做法会重复扣留。原始余额不能换成“已扣完的可用额”后仍标作 SettledCash。
费用、订单占款、未结算及其他义务由原资金检查处理；缺少义务证据不按零。

同一份保留现金可以按用户声明用于生活费和手续费缓冲，当前 CashPolicy 不要求再建两个重复的保留账户，也不猜其中各自金额。用途明确后不再当作未知用途，但原比例／最低额的实际生效值、可支用状态和适用性仍须核对。

“费用缓冲”是现金安排，实际手续费是交易成本：预留不是已经支付手续费，实际交易仍按有依据的费用模型计入现金账一次。不得在原保留之外再默认加一份固定手续费缓冲，也不得把同一笔已计入的费用再次作为 OTHER 扣除。当前离线合同要求买入金额加实际费用不超过扣除保留和其他义务后的可花现金，交易后仍守住原现金底线；它尚未把保留额拆为可消耗的手续费部分与不可占用的生活费部分，不能据用途声明自动放宽底线。

保留要求高于可用现金时，解释不足并限制新增；不因此自动借款、转入外部资金或强制卖出。
减仓和熔断仍走原内核及已批准的处置规则。

## 4. 定投计划和实际到账是不同事实

定投计划只用于说明未来意向，不授权银行转账，不提前增加当前预算或购买力。

1. 已核来源确认资金进入指定账户，记录为外部本金流入。
2. 等资金按券商规则可支用后，使用新账户快照重新计算保留现金和组合预览。
3. 账户净值已含该笔本金时，不再将它作为额外未来现金加一次。
4. 绩效和回撤使用适用的资金流调整口径；存款不是盈利，取款不是亏损，不靠重设高水位抹去历史风险。

到账会改变净值与现金；损失额度按已批准的表达式或曲线处理，不因新增本金额外放宽政策。

复用既有 `extract_external_cash_flow`、`cash_flow_adjusted_return` 和事件/状态账本。
现有期末资金流约定不能宣称覆盖任意盘中到账时点；缺少时间及连续性证据时保留缺口。
银行或其他券商之间的移动还须按观察范围区分内部调拨和外部流入，不能在总览重复记本金。

从账户提取生活费属于实际发生且有来源证明的外部资金流出，不能当作策略投资亏损；尚未扣账的明确提款义务与已扣后的余额须核是否重叠。预留现金的用途声明不证明提款已经发生、资金已经到账，也不授予转账或卖出权限。

## 5. 三档配置共享同一资金规则

智能模式选择保守、均衡或进取；高级设置只调整已开放字段。两种模式共同消费账户范围、
有效 CashPolicy、数量费用接口和原 RiskEngine，不提供绕过资金义务或账户风险上限的入口。

三档改变风险预算与组合候选，不自动修改用户现金底线。进取档允许有限超过指定基准的设计方向，
须有预先确定的比较方法、允许幅度和期限；“稍微超过”不能转成无限制。
严格规则仍可作为对照。采用资格与研究观察分开，不因候选暂未满足采用门槛就删除其研究记录，
也不为通过门槛变更已冻结窗口。

最大回撤、波动和尾损失的角色与单位必须分别声明。现有研究参数
`protected_capital_basis` 属于风险曲线的资金参考基准，不是保留现金、家庭应急金或需要再次扣除的金额。
该字段的来源和曲线含义由工程核定；个人可承受亏损金额、比例与用钱期限仍须用户或有效政策给出。

三档累计回撤触线的通用字段见 [风险政策模板](tqqq-risk-policy-draft.zh-CN.md)；具体数值和个人认可记录来自私有来源，不随模板发布。认可候选不等于它适合任意资金用途，也不替代运行曲线校准。用钱日期不确定须保持不确定，不能因持续收入或定投计划就假定长期不用或自动提高风险。已有现金保留规则继续复用，未来工资不提前计入购买力，未明确的用款不自动当零或新增一笔假设扣留。个人选择和用途只从私有来源绑定。

## 6. 本次接线与结束条件

只接 TQQQ/IBKR 的原离线预览入口，不铺开所有平台或新建配置框架：

- 离线入口读取已加载 runtime 的原比例、最低金额与策略执行保留比例；显式注入与这些值一致、范围和时效绑定的人工配置来源。复用 CashPolicy 生成保留要求，不要求调用方再手算一份。
- 一份保留要求接入已有现金证据桥，智能与高级模式、三档均使用同一 packet。最低金额进入保存指纹，即使暂时由比例主导，也不能在读回时忽略其改变。
- 来源、版本、时点、配置摘要及保留条目身份随原草稿保存和消费预检；重复使用同一条目不再次扣除，冲突不覆盖。未映射的其他 RESERVE 不能仅凭金额相同就合并，亦不能直接叠加。
- 复用当前账户范围、已到账资金流及状态合同；缺少真实来源或金融阈值就显示缺项。现金预览可先显示人工资金计算结果，但不替代有效风险政策或产生可用草稿。

人工验证须覆盖比例与最低额各自主导、两者相等、显式零、资金不足、同一保留重复输入、
订单义务不重复扣、到账前后、重复到账事件、资金流调整，以及两种模式一致。
交付以预览读回和原现金账守恒为终点，不产生真实配置或执行资格。

上述人工接线及合成验证已完成，接口见 [TQQQ 离线接线](tqqq-offline-risk-wiring.zh-CN.md)。原生余额未预扣保留；原账户适配器只扣一次保留和不重叠的其他义务，交易现金账仍仅记录证券与费用现金流。

这条入口没有联网读取真实运行配置。配置来源仍为明确的人工声明，读回显示 `FROZEN_INPUT_NOT_SERVING_CONFIG`；真实已加载设置的受保护读回、完整资金义务与适用费率/权限仍需独立证据。按比例模式在原解析规则明确的情况下可以使用已解析的默认固定额；未知或读取失败不能当成已解析默认。

独立的[实际承载版本现金设置只读诊断](account-cash-settings-readback.zh-CN.md)可核既有服务元数据及固定环境声明，严格区分缺失、显式零和未读 Secret 引用，不输出个人数值或其低熵哈希。它不读取账户报告，也不证明进程实际消费、资金可支用或风险政策有效；目标绑定不符时不把不同来源硬拼为有效现金配置。

到账验证使用已有完整累计资金流和调用者明确提供的资金流调整指数：本金增加只反映在新 NAV 和新 SettledCash，不算收益、不累计重复到账，也不重置高水位。尚未实现从真实盘中到账流水自动生成该指数；原期末资金流辅助函数不能冒充这一能力。没有银行或券商转账、定投调度或自动风险曲线扩额。

现金规则的离线接线不代表真实保留值、完整资金义务、有效风险政策、生产配置消费者和金融采用均已完成。
